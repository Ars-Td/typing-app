# 返信打 MVP 仕様書

IT エンジニアのチャット返信を模したタイピングゲームの MVP 仕様。

**UI 方向性:** パターン A「Workspace Pop」を採用（モック比較で決定）。見た目の正は [`mockups/pattern-a/`](../../mockups/pattern-a/)。

## 実装上の前提

- React SPA と Hono API を **1 つの Cloudflare Worker** にまとめる。
- タイピング問題とプレイ結果は **Cloudflare D1** に保存する（ローカル D1 と本番 D1 は分離）。
- キー入力はブラウザ内で記録・集計し、**ゲーム終了時にまとめて保存**する。高頻度なキーイベントを API に送らない。
- 初回アクセス時に匿名 ID を生成してブラウザに保存し、同じブラウザの履歴を識別する。ログイン機能は持たない。
- 個人情報は保存しない。

---

## 1. 概要

相手からメッセージが届き、決められた返信文をローマ字で打ち切って送信する。題材は実際のエンジニア業務で使いそうなコミュニケーションとする。

例:

- 相手: `PR #123 のレビューお願いできますか？`
- 返信: `確認します。少々お待ちください。`

想定する題材:

- 確認・レビュー依頼
- バグ報告
- 進捗報告
- 質問
- 顧客への連絡
- `@` メンション
- 多少 Markdown のような記法を取り入れた構造的な文章
- Issue / PR 番号
- 英数字や記号を含む文章

URL のように、タイピングゲームとして入力負荷が高すぎるものは出題しない。

### 世界観

- 今どきの IT 企業っぽいテイスト
- 基本トラブルが多めな会社
- 主人公はフルスタックに Web アプリを開発する部署に配属されている
- 主人公は漢字が大好きで、言えば言うほどカッコいいと思っている。文章作りがうまい（返信文のトーンに反映する）

### 確認済みの前提

- 1 プレイは時間制限（寿司打型）
- 画面上の返信は日本語、入力はローマ字（英数字・記号はそのまま）
- デスクトップ Web。モバイルは MVP 対象外

## 2. 画面構成とフロー

```
ホーム → プレイ → 結果 → ホーム
ホーム → 分析 → ホーム
結果 → 再挑戦（同設定でプレイ） / 分析
```

| 画面 | 役割 |
| --- | --- |
| ホーム | 難易度・制限時間を選んで開始。分析への導線。自己ベスト年収があれば表示 |
| プレイ | Slack 風タイムラインで返信をタイピング。時間切れで結果へ |
| 結果 | メインスコア「ゲーム内年収」とサブ指標 |
| 分析 | 通算の苦手キー・指・動き |

プレイ中に中断した場合はスコアを確定せずホームに戻る。MVP では途中保存なし。

---

## 3. 1 プレイのルール

### 3.1 制限時間

ホームで選択する。

- **1 分 / 2 分 / 3 分**
- デフォルトは **2 分**

終了条件は残り時間 0。入力途中の返信は未送信とし、その件の報酬は加算しない。

### 3.2 1 スレッドの進行

1. 相手メッセージ（1〜数通の短文）を表示する
2. 自分の返信文が入力欄の「お手本」として日本語で出る
3. ユーザーはローマ字で打つ。一致した文字が確定していく
4. 全文一致で送信できる（Enter または送信ボタン）。1 件完了として報酬を加算する
5. 次のスレッドへ進む。問題は難易度プールからランダム。同一プレイ内では使い切るまで重複しない。使い切ったらループしてよい

お手本は常に全文見える。今打つ位置はハイライトする。

### 3.3 入力仕様

- IME は使わない想定。キー入力はそのままローマ字列として評価する
- 日本語部分は一般的なローマ字表記の揺れを受け付ける
  - し = `shi` / `si`
  - つ = `tsu` / `tu`
  - ち = `chi` / `ti`
  - ふ = `fu` / `hu`
  - ん = `n` / `nn`
  - その他、よくあるヘボン式 / 訓令式の揺れ
- 英数字・記号・Markdown・`@mention`・`#123` は表示と同じキー
- 日本語の句点・読点は `.` と `,` で入力する
- 改行を含む上級問題では、未完了時の Enter は改行のみ。全文完了後の Enter、または送信ボタンで送信する
- Backspace で直前の未確定 / 誤入力を消せる
- **ミス:** その位置で期待されないキーを押した回数。訂正してもミス回数は残す

## 4. 難易度

難易度は出題プール・文章の長さ・基本報酬を変える。制限時間の選択とは独立。

| 難易度 | 呼称 | 返信の傾向 | トーン |
| --- | --- | --- | --- |
| 初級 | 新米エンジニア | 短い、記号少なめ、単純な確認・承知 | 初々しい。丁寧だが漢字は控えめ〜好きが出始める |
| 中級 | 慣れてきたエンジニア | やや長文。メンション、Issue / PR、軽い Markdown、英数字 | 調子に乗り始める。漢字多め・決め台詞っぽい |
| 上級 | つよつよエンジニア | 長め・複数行。引用、技術用語、記号多め | 絶対的自信。漢語・断言・構造化された文 |

MVP の出題数目安: 各難易度 **12〜15 スレッド**（相手文 + 固定返信）。

## 5. スコア（ゲーム内年収）

メインスコアは **ゲーム内年収**。返信を 1 件送り終えるたびに報酬が加算され、終了時の合計を年収として大きく表示する。

年収はその **1 プレイのスコア** である。通算の自己ベスト年収は結果画面と分析画面のサマリに出す。

### 5.1 1 件の報酬

円、整数。

```
報酬 = round(基本額 × 速度係数 × 正確性係数)
```

**基本額**（難易度の仕事単価）

| 難易度 | 1 件の目安 |
| --- | --- |
| 初級 | 8 万〜25 万 |
| 中級 | 20 万〜50 万 |
| 上級 | 40 万〜90 万 |

複数行・記号が多い問題は基本額を厚くする。

**速度係数**

- その 1 件の「正しい打鍵数 / 所要秒」を CPM 化する
- 基準 CPM との比: 初級 180 / 中級 220 / 上級 260
- 係数は **0.7〜1.5** でクランプ

**正確性係数**

```
max(0.3, 1 - ミス率 × 1.2)
ミス率 = その件のミス数 / その件の総打鍵
```

プレイ中 HUD に累計年収をリアルタイム表示する。結果画面のヒーロー数字はこの累計。

---

## 6. 結果画面のサブ指標（そのプレイ）

年収とは別に、以下を表示する。

| 指標 | 定義 |
| --- | --- |
| 入力速度 | **WPM** と **CPM**（正しい打鍵のみ、制限時間ベース） |
| 正確性 | `(総打鍵 - ミス) / 総打鍵` |
| ミス数 | 期待されないキーを押した回数の合計 |
| 最大連続入力数 | ミスなく連続して正しく打てた打鍵の最大 |

コピーは世界観に合わせてよい。数字の意味は上表で固定する。

導線: 再挑戦 / ホーム / 分析。難易度と制限時間も回顧表示する。

## 7. タイピング分析（通算）

各プレイ終了時に集計を保存し、専用画面から確認する。

### 7.1 苦手キー

キーごとに入力回数・ミス回数・ミス率。ミス率が高い順。母数が **20 回未満** のキーは「参考」扱い。

### 7.2 苦手な指

JIS 日本語キーボードの標準ホームポジション（左小指〜右小指 + 親指）。Shift を伴う記号は、その文字キーの指に寄せる。

### 7.3 苦手な動き

連続する 2 キー（バイグラム）の出現数・ミス数・ミス率。ミスはその 2 打目がミスしたとき。上位のみ表示する。

### 7.4 表示

リストと簡単な棒グラフ。プレイ回数が少ないときは空状態。

---

## 8. 画面要件

ホーム・プレイ・結果・分析の要件は当初仕様どおり。アプリ名は **返信打**。CTA は「シフト開始」。結果は「シフト終了 · 査定結果」。

---

## 9. UI / UX 方針

採用: **A. Workspace Pop**。アクセントはピンク / ライム / スカイ。サイドバーは濃色オーベルジン。本文エリアは白。

---

## 10. MVP 外

- アカウント・ランキング・シェア
- カスタムお題・ユーザー投稿
- かな入力、英語のみモード
- URL タイピング、音声、BGM 必須
- 高度な統計、中断再開、オンライン対戦
- モバイル対応
